# Azure DevOps PR Review for OpenCode — 0.5.2

This release moves the tested host to OpenCode 2.4.2. OpenCode 2.4.2 was
compared with 2.4.1, the last version studied, and needs no change to how
AZPR runs a review: in the three smoke runs of the host fixtures, private
sessions were sent on 2.4.2 what they were sent on 2.4.1, request by request,
once what differs between any two runs (paths, IDs, times) is set aside. The prompt files
are those of 0.5.1, no setting is new, and your settings and saved reviews
are used as they are.

## What changed

- **`/pr-check` notes another OpenCode version instead of warning of it.** On
  an OpenCode other than the tested one, and on one that does not say its
  version, the OpenCode row is `ok` and names the tested release in a note.
  It was a WARNING, which read as if something were wrong: reviews run on an
  OpenCode V2 host that provides what AZPR needs, and what a host lacks is
  still reported where it matters (the Project boundary WARNING without the
  permission hook, a command's error or receipt that names a missing method,
  the host's plugin list; see [compatibility](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/ARCHITECTURE.md#compatibility)).
  A script that looked for the OpenCode WARNING should read the OpenCode
  row's note instead.
- **A turn whose prompt is gone says what is known.** OpenCode 2.4.2's
  terminal UI can take the last prompt back (Esc twice before the model
  answered), and in a reviewer's session that prompt is AZPR's. Measured on
  2.4.1 and 2.4.2 by calling the routes the terminal UI uses, in its order,
  the turn fails as interrupted. Where the prompt is gone before AZPR reads
  the session, the error now says that the prompt is not among the session's
  messages exactly once and that it may have been taken back or removed by a
  compaction; before, it named only a compaction. [Debugging](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/DEBUGGING.md#diagnosis-order) says how a prompt is taken back
  and what the receipt then shows. Stop a run with `/pr-stop`, not in one of
  its sessions.
- **Phone notifications.** From OpenCode 2.4.2 on, OpenCode's mobile app can
  notify a paired phone when a top-level session's run ends: "Finished" after
  a run that succeeded with a model step, "Failed" after one that failed.
  AZPR's private sessions are top-level sessions, so one review can send
  several notices, and a phone newly registered without settings gets them all.
  AZPR leaves these settings alone: set the phone to notify only when
  attention is needed (questions and permission requests), or mute the
  `[AZPR …]` sessions there. This was read from OpenCode's source; OpenCode
  accepts only its own relays as a phone's address, so no notification was
  received in a test.
- **One place names the tested release.** `TESTED_HOST_VERSION` in
  `src/host.mjs` is the release AZPR is tested with: CI installs the release
  it names, the installer's closing message and the contributor's
  instructions read it, and a test holds the README's badge and Compatibility
  row to it. Comments and documents date a host behaviour that AZPR relies on
  as "OpenCode A to the tested version", and each such behaviour was checked
  again on 2.4.2.
- OpenCode 2.4.2 offers image and video generation to a conversation as
  Code Mode tools instead of tools of their own. Private sessions are
  offered neither, as before; the host fixture now also checks every private
  request of its run for their names.

## Upgrading OpenCode

AZPR 0.5.1 runs on OpenCode 2.4.2 as well (with the OpenCode WARNING row in
`/pr-check`), and 0.5.2 on 2.4.1, so the order of the two upgrades does not
matter.

From 2.4.1, OpenCode 2.4.2 adds no database migration, so going back to
2.4.1 later needs no restored database. Stop the background service, install
2.4.2 and start the service again; use `sudo` for the global install if your
npm prefix needs it:

```sh
opencode service stop &&
  npm install -g @opencode/cli@2.4.2 &&
  opencode service start
```

If the install fails, the service is still stopped: start it with
`opencode service start`. To go back, run the same commands with 2.4.1.

From a release before 2.4.0, back up OpenCode's database first: 2.4.0 adds
migrations, and going back past it needs the backup. The
[0.5.1 release notes](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/releases/v0.5.1.md#upgrading-opencode)
give the commands for the backup, the upgrade and the way back; put 2.4.2
where they install 2.4.1.

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.5.2
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.5.2'
```

Add only one of them. Then open OpenCode's terminal UI and type `/pr-setup`;
the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/QUICKSTART.md)
walks through it and shows the way without the terminal UI.

## Upgrading AZPR

For an entry that `opencode plugin add` created, add 0.5.2 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.5.1:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.5.2 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running. Running only the first command
leaves the previous version running. For an entry with options, change only
its `package` value. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/README.md#upgrading)
for the details. Settings, the PAT file and review records remain in place,
and no setting is new or required. Coming from 0.4.x, the settings need the
update that the
[0.5.0 release notes](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/releases/v0.5.0.md)
describe.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

Manual copying needs the same 33 files as 0.5.1.

## Known limitations

New with OpenCode 2.4.2: the phone notifications above.

Newly documented; 0.5.1 behaves the same: with `shell: "ask"` or
`"inherit"`, a shell request of one of AZPR's sessions (a reviewer's, say)
that a person declines without a reason fails that session's turn;
OpenCode's full-screen terminal UI and desktop app give none in AZPR's
sessions (`opencode mini` asks for one, which the model then receives as the
command's result). Where the decline ends the step, OpenCode records the end
of that execution as a shutdown, so the turn has no marker of its end, and
what the session does until a later marker, while AZPR waits for it, counts
to that turn; AZPR takes no answer of it. Approve the command, or keep
`shell: "deny"` where AZPR's sessions should run none; see
[debugging](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/DEBUGGING.md#diagnosis-order).

Not changed by this release: the limitations that the
[0.5.1 release notes](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/releases/v0.5.1.md#known-limitations)
list, which the
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/VALIDATION.md#known-limitations)
keeps current.

## Compatibility and validation

The tested target is OpenCode CLI **2.4.2** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. `/pr-check` notes other OpenCode versions in its OpenCode row.
OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The prompt files under `src/prompts` are unchanged. The
[comparison of OpenCode 2.4.2 with 2.4.1](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/VALIDATION.md#opencode-242-compared-with-241-2026-11-27)
says what was measured on which version and what was only read from
OpenCode's source, and the
[release candidate's acceptance](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.2/docs/VALIDATION.md#052-release-candidate-acceptance-2026-11-27)
what 0.5.2 itself ran on: the host fixtures on OpenCode 2.4.2, the unchanged
candidate on 2.4.1, and copies on 2.4.1 to 2.3.0.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts; the source archive also contains the
documentation, installers and settings example. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.5.2.tar.gz`, with checksums in `SHA256SUMS`.
