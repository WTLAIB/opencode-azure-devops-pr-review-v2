# OpenCode Azure DevOps PR Review V2 — 0.2.0

A completed review can now preview or publish its comments automatically,
without another `/pr-comment` command. This is opt-in: existing installations
keep the manual workflow until you select a setting or command flag.

## What changed

- `afterReview` selects `none`, `preview` or `publish` separately for `quick`,
  `review` and `deep`. Every mode defaults to `none`.
- One flag immediately after the PR URL (`--preview`, `--publish` or
  `--no-comment`) overrides that setting for a single review. Mistyped flags
  there produce an error; they do not fall back to automatic publication.
- A COMPLETE review starts the comment step as its own run, with a STARTED
  notice and receipt. `/pr-stop` cancels it. A stopped review starts no step;
  a review without findings needs no extra planning or model request. A busy
  conversation or PR skips the step and gives the command to run manually.
- Automatic publication holds individual items containing mentions, images,
  active HTML or script/private-file links in the saved preview. Other items
  are posted and read back. Ordinary links and unambiguous literal code are
  allowed; mentions are checked in code too. Inspect held items before using
  the explicit `/pr-comment <review-id> --publish` command.
- When every finding is already discussed on the PR, automatic publication
  reports `NOTHING_TO_POST` instead of adding another summary.
- Quick comments keep their "not independently verified" disclosure;
  severity and incomplete coverage do not block the whole publication.
- `/pr-check` shows the configured automatic action and posting identity as
  information. Setup errors identify the settings problem without values.
- The automatic-publication HTML checks read long tag-like text in linear
  time, avoiding the slowdown found during review of this feature.

For a one-off preview, substitute your own authorized Azure PR URL:

```text
/pr-review https://dev.azure.com/YOUR_ORGANIZATION/YOUR_PROJECT/_git/YOUR_REPO/pullrequest/123 --preview
```

Use `--publish` in the same position to request automatic publication, or
`--no-comment` to suppress a configured automatic action for that run.
To default to previews, add this to AZPR's settings and restart the service:

```json
{
  "afterReview": {
    "quick": "preview",
    "review": "preview",
    "deep": "preview"
  }
}
```

See [automatic comments](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.2.0/docs/COMMENTING.md#automatic-comments-after-a-review)
for the per-item checks, cancellation and publication receipts. Review prompts
and the verified versus quick review methods are unchanged.

## Installation

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.2.0'
```

Follow the [quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.2.0/docs/QUICKSTART.md)
for `/pr-setup`, a private PAT file, service restart and your first review.
The source archive includes `install.sh` for manual installation. Use one
installation method per OpenCode profile. This is a Git package release; it
does not publish an npm registry package.

## Upgrading from 0.1.0

For a native installation, edit the existing AZPR entry in the OpenCode
configuration's `plugins` list: change
`github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.1.0` to
`github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.2.0`. If the entry is an
object, change only its `package` value; preserve `options.settingsFile` and
other options. Keep one AZPR entry, then restart the OpenCode service. Native
settings remain outside the package cache, and missing `afterReview` values
default to `none`.

For a source installation, extract the new archive and run its installer:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

This preserves operational settings and adds missing defaults. Keep the PAT
file and private state directory in place. Neither installation method needs
you to repeat `/pr-setup` for an already working configuration. For the usual
managed OpenCode service, restart with `opencode service restart`; if you run
`opencode serve` yourself, restart that process instead.

## Compatibility and release assets

The tested target remains OpenCode CLI **2.1.2**, Node.js **22.23.3**, Ubuntu
**22.04.5** under WSL2, and Azure DevOps Services REST API **7.1**.
[Validation](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.2.0/docs/VALIDATION.md)
separates offline tests, real-host fixtures using fake services, and earlier
live Azure/model evidence. Release acceptance uses isolated profiles; it does
not run live models or publish Azure test comments. Azure DevOps Server and
other operating systems remain unvalidated.

Release assets are the source archive
`opencode-azure-devops-pr-review-v2-0.2.0.tar.gz`, `azpr-live-demo.mp4`, and
`SHA256SUMS`. Verify downloaded assets with `sha256sum -c SHA256SUMS`.
The video is the unchanged recording from v0.1.0 on 2026-10-22; it shows the
manual review, preview and publication workflow, not the new automatic step.
The [demo guide](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.2.0/docs/DEMO.md)
records its source commit, model, edits and limitations.
