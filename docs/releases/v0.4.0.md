# Azure DevOps PR Review for OpenCode — 0.4.0

This release makes the everyday commands shorter. A comment preview follows
each review by itself, no `/pr-comment` command needs a review ID, a preview
ends with the commands for the next step, and every command answers `--help`.
Two reports say more: a review that ran without content search states it, and
a verifier that confirms a finding without a correction is asked which it
means. The reviewer and verifier instructions are those of 0.3.7, and the
tested host stays OpenCode 2.2.4.

**Two defaults change** (see "Upgrading AZPR" below): a preview follows every
COMPLETE review, and large PRs run eight reviewer sessions at once instead of
four.

## What changed

### A review, then its preview

```text
/pr-review <PR URL>
```

When the review is COMPLETE and has findings to comment on, a separate comment
run plans a preview: the comments as they would be posted. It uses a model and
posts nothing. `afterReview` is now `preview` for every mode; `--no-comment`
after the URL gives a review without a preview, and `afterReview: none`
restores the earlier behavior. Publication is still never a default.

### Commands without a review ID

```text
/pr-comment --exclude F-1,R-2                     leave F-1 and R-2 out
/pr-comment --severity F-3=low,R-4=medium         publish F-3 as low and R-4 as medium
/pr-comment --exclude F-1,R-2 --severity F-3=low  both in one command
/pr-comment --publish                             post the saved preview
/pr-comment --list                                the reviews saved for this conversation
```

- `--exclude`, `--severity` and `--reset` no longer need a review ID. Like
  `--publish` and `--show`, they act on the conversation's **current review**:
  the one completed or used there last. Naming a review by its ID once makes
  it the current one, and this survives a restart. In one of a review's own
  sessions the current review is that review.
- So that a command without an ID can be checked at a glance, the start notice
  and the receipt of every comment run name the review and its PR:
  `Acted on review 1a2b3c4d (/pr-review) of PR #123 in project/repository`.
- A preview's receipt ends with the commands for the next step, written
  without the ID and with that review's own finding IDs. Each adjustment list
  replaces the saved one, so an example keeps the adjustments already saved.
- `/pr-comment --list` shows the saved reviews with their IDs, PRs and state,
  and every command answers `--help` with its usage and examples. Neither uses
  a model or makes an Azure DevOps request.
- OpenCode's command list shows one line of a command's description and cuts
  what does not fit. The descriptions now start with what the command is for
  and point to `--help`.

A review ID before the option still names any saved review of the
conversation, for example `/pr-comment 1a2b3c4d --publish`.

### Reports that say more

- **A review without content search says so.** When the repository archive is
  larger than `azure.archiveMegabytes` allows (100 MB by default), or is one
  AZPR cannot read, reviewers cannot search file contents for callers and
  other uses of the changed code. Until now only the models were told. The
  report's limitations and the receipt now state it, with the setting's value
  where a larger one would help.
- **A confirmation states its correction.** A verifier that confirms a finding
  whose suggestion is only a placeholder, such as "N/A" or "No correction
  needed.", is asked in the same session to state the correction or to reject
  the finding. Left as it is, the finding is NEEDS_INFO: it stays in the
  report and gets no comment. In the verifier results of our stored benchmark
  runs this happened in 3 of 15,376 confirmations, all three from GPT-6 Luna
  verifiers whose own reason refuted the finding; the check sent back no
  other confirmation.

### Parallelism

`workflow.parallelSessions` is 8 (was 4) and `azure.concurrency` is 6 (was 3).
They matter for a PR of more than one shard (25 files by default): on a
316-file test PR these values cut a review from 719 to 393 seconds without a
provider retry or throttling. That is one measurement with one provider.
Lower `parallelSessions`, to 4 for example, when your provider limits the
request rate, or with OpenCode's claude-agent provider on a machine with
little memory: each of its sessions keeps a process of about 200 MB for
minutes after it ends.

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.0
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.4.0'
```

Add only one of them. Follow the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.0/docs/QUICKSTART.md)
for a private PAT file, `/pr-setup`, a service restart and the first review.

## Upgrading AZPR

**Check whether the changed defaults reach you.** They apply to a setting your
`settings.json` does not name:

- A file written by `/pr-setup` names neither `afterReview` nor the two
  parallelism settings, so after the upgrade a preview follows every COMPLETE
  review (one more model request for about four findings) and large PRs run
  with 8 sessions and 6 Azure DevOps calls at once. To keep the earlier
  behavior, add
  `"afterReview": { "quick": "none", "review": "none", "deep": "none" }`,
  `"workflow": { "parallelSessions": 4 }` and `"concurrency": 3` under
  `azure`, then restart the OpenCode service.
- A file installed with `install.sh` names all of them and keeps its values.
  Change them yourself to get the new defaults.

`/pr-check` shows the `afterReview` value of each mode.

For an entry that `opencode plugin add` created, add 0.4.0 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.3.7:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.0 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running: OpenCode 2.2.4 switches the running
service to 0.4.0 within seconds, without a restart, and
`opencode plugin list` should then show a single `azpr` row with 0.4.0. Running
only the first command leaves the previous version running. For an entry with
options, change only its `package` value; the OpenCode service then downloads
0.4.0 with its own network settings. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.0/README.md#upgrading)
for the details. External settings, the PAT file and review records remain in
place, and no setting is new or required. Reviews saved by 0.3.7 keep their
previews and adjustments, and the commands without an ID work on them.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

The installer keeps every value `settings.json` names. A file from before
0.2.0 that has no `afterReview` gets it with the new default, `preview`.
Manual copying needs the same files as 0.3.7.

## Compatibility and validation

The tested target is OpenCode CLI **2.2.4** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The prompts under `src/prompts` are unchanged, so reviews find and verify as
in 0.3.7; the runtime, the command texts and the defaults changed. The
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.0/docs/VALIDATION.md#040-release-candidate-acceptance-2026-11-14)
lists the offline and real-host checks with fake services. No live review with
a real model was run on this candidate.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts; the source archive also contains the
documentation, installers and settings example. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.4.0.tar.gz`, with checksums in `SHA256SUMS`.
