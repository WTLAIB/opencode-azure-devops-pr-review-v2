# Azure DevOps PR Review for OpenCode — 0.5.4

This release fixes two defects that the recheck for 0.5.1 found and left for
the next version: typing a finding's ID into the terminal panel's list of
findings could select another finding, and a reviewer's answer that reached
the model's output limit failed its pass as if someone else had written into
its session. The tested host stays OpenCode 2.4.2. The prompt files are those
of 0.5.3, no setting is new, and your settings and saved reviews are used as
they are.

## What changed

- **Typing a finding's ID in the list of findings selects that finding.** In
  the terminal panel's list of findings (**Adjust findings…**), OpenCode's
  own search listed the best match first: among twelve findings, `F-1`
  listed F-11 first, and Enter opened F-11's dialog. The list now answers by
  a search of AZPR's own. An ID typed in full lists the finding of that ID
  alone, and no row where the list has none, so that no other finding stands
  in for one that is not offered. Anything else lists the rows whose title
  holds every word typed, in the order they are listed. The list is drawn without
  its headings ("Findings", "Then"), and each row still shows its level or
  "left out".
- **An answer that reaches the model's output limit is no longer taken for
  another message.** After a response that reached the model's output
  limit, OpenCode asks the model to go on, with a message of its own. AZPR
  0.5.3 took that message for someone else's: it failed the turn, ran the
  shard once more in a new session, which failed the same way, and its
  receipt spoke of another message in the turn. Now a response of the turn
  that reached the limit (`finish=length`) is the turn's own outcome:
  - nothing of that turn is taken, and it fails as `output-limit` with an
    error that names the limit;
  - where the session then has no usable answer (its first answer was cut,
    say), a reviewer shard of several files is split in two, as for a full
    context, and its halves run instead;
  - a stage that fails as `output-limit` is not run again in a new session,
    since the same input is likely to be cut again: a shard of one file, a duplicate
    check, a rating or a planning page fails then, and degrades as any of its
    failures does;
  - a correction or follow-up turn that is cut leaves the latest usable
    answer standing, where there is one (`repair=failed:output-limit`,
    `follow-up=failed:output-limit`).

  Where a compaction was attempted in the turn, or a later response ended it
  otherwise (a person's interrupt, a provider's error, a broken stream), the
  turn is classified as before.
- **A host fixture for answers cut by the output limit.**
  `tests/host-v2-output-limit.mjs` runs two reviews on the real host with a
  fake model: one whose cut answer OpenCode has the model continue, which
  AZPR fails and splits, and one where every answer is cut until OpenCode
  gives up, where no half of one file is run twice. It also holds the finish
  OpenCode records on such a step, and runs in CI.

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.5.4
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.5.4'
```

Add only one of them. Then open OpenCode's terminal UI and type `/pr-setup`;
the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.4/docs/QUICKSTART.md)
walks through it and shows the way without the terminal UI.

## Upgrading AZPR

For an entry that `opencode plugin add` created, add 0.5.4 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.5.3:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.5.4 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running. Running only the first command
leaves the previous version running. For an entry with options, change only
its `package` value. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.4/README.md#upgrading)
for the details. Settings, the PAT file and review records remain in place,
and no setting is new or required. Coming from 0.4.x, the settings need the
update that the
[0.5.0 release notes](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.4/docs/releases/v0.5.0.md)
describe. OpenCode stays at 2.4.2; coming from an earlier OpenCode, the
[0.5.2 release notes](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.4/docs/releases/v0.5.2.md#upgrading-opencode)
give the upgrade.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

Manual copying needs the same 33 files as 0.5.3.

## Known limitations

Changed by this release: an answer that reaches the model's output limit is
still not taken, but it no longer fails as someone else's message, a shard of
several files is split where the session has no usable answer, and a stage
that fails as `output-limit` is not run again with the same input. A shard of
one file whose answer is cut fails that pass for the file. Fewer files per
shard (`workflow.shardFiles`) shorten a review's answers, and a model that
allows longer answers can help. See
[debugging](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.4/docs/DEBUGGING.md#diagnosis-order).

Not changed by this release: the other limitations that the
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.4/docs/VALIDATION.md#known-limitations)
keeps current.

## Compatibility and validation

The tested target is OpenCode CLI **2.4.2** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. `/pr-check` notes other OpenCode versions in its OpenCode row.
OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The prompt files under `src/prompts` are unchanged. The
[release candidate's acceptance](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.4/docs/VALIDATION.md#054-release-candidate-acceptance-2026-11-28)
says what 0.5.4 ran on and what was only read from OpenCode's source.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts; the source archive also contains the
documentation, installers and settings example. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.5.4.tar.gz`, with checksums in `SHA256SUMS`.
