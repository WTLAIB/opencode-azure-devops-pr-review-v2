# Azure DevOps PR Review for OpenCode — 0.4.1

This release moves the tested host to OpenCode 2.3.0 and fixes two things
that went wrong there: a review woke the conversation's own model, and a model
stream that broke off mid-answer failed its stage. AZPR's private sessions are
now sessions of their own, so OpenCode lists them next to your conversations;
AZPR deletes them when a review ends, except the one that holds the report.
The reviewer and verifier instructions are those of 0.4.0, and no setting is
new.

**Upgrade AZPR before OpenCode.** 0.4.0 on OpenCode 2.3.0 has both problems
below; 0.4.1 runs on OpenCode 2.2.4 and 2.3.0.

## What changed

- **A review no longer wakes your conversation's model.** OpenCode 2.3.0
  hands every answer of a child session to its parent and lets the parent's
  model respond to it. AZPR's private sessions were children of the
  conversation, so on 2.3.0 the conversation's model, with its edit and shell
  tools, received the reviewers' raw output and AZPR's notices and answered
  each one: 7 of the 12 model requests of a 2-file review in the test fixture,
  and 30 of 64 in a 120-file one. Private sessions are now sessions of their own,
  created where the conversation is. In a fixture review, the 34 requests the
  reviewers, verifiers and comment planners were sent are byte-identical to
  those of 0.4.0.
- **An interrupted model stream no longer fails the stage.** OpenCode 2.3.0
  retries the interrupted step by itself instead of asking the model to
  continue. AZPR 0.4.0 did not recognise that: it ran the stage again in a
  new session, and a second interruption failed the review. 0.4.1 takes the
  retried step's answer in the same session; the receipt counts such steps as
  `step-retries`.
- **Private sessions in the session list.** OpenCode lists a session without
  a parent like a conversation, and a plugin cannot archive one, so AZPR's
  sessions appear next to your conversations, titled `[AZPR <id>] …`. When a
  review ends, AZPR deletes its sessions at once, except the one that holds
  the report or draft, which the receipt names; a comment run keeps none,
  since its receipt carries the preview or the publication result. Until now
  a completed review kept all of its sessions until it was evicted. A
  review's receipt says how many sessions were deleted (`Session notice`),
  and the kept session is deleted with its review (the newest 20 reviews are
  kept).
- **With `debug.enabled`, every session is still kept** until its review is
  evicted, so each review adds all of its sessions to the list. Turn debug
  off for everyday use. `deletePrivateSessions: false` keeps everything too.
- **An interrupted review leaves its sessions.** When OpenCode restarts while
  a review runs, AZPR has not recorded that run's sessions yet and does not
  delete them later. They are titled `[AZPR <id>] …`; delete them yourself.
- **Deletions that fail are not forgotten.** A session whose deletion failed
  or timed out stays on record: it is deleted with its review, or, when no
  review keeps it, tried again after every later run.
- **Sessions are marked.** Each private session carries `metadata.azpr` with
  its run, role and conversation (and, for a comment run, the review), so
  tools that list sessions can tell AZPR's sessions from conversations.
- **A stopped tool call ends at once.** When OpenCode stops a reviewer's tool
  call, the call ends instead of waiting for its Azure DevOps request. The
  request only that call waits for is aborted; a file, a recursive listing or
  the repository archive, which the run's other sessions may be waiting for,
  is still read to the end and kept for them.

Two things to know on OpenCode 2.3.0, now described in the
[README](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.1/README.md#configuration):

- A model entry that lets the provider choose the model for each session,
  such as GitHub Copilot's **Auto**, cannot be an AZPR model. AZPR refuses a
  request on another model than the configured one, and `/pr-check` does not
  detect such an entry. Name a concrete model.
- While a provider's host cannot be reached (no DNS answer, no route),
  OpenCode 2.3.0 retries the request for up to an hour. AZPR allows those
  retries, so a review waits instead of failing; `/pr-stop` ends it.

## Upgrading OpenCode

Upgrade AZPR to 0.4.1 first (see below), then OpenCode. OpenCode 2.3.0 adds no
database migration to 2.2.4, but back up the database before any upgrade:

```sh
opencode service stop
mkdir -p ~/opencode-db-backup && cp -p ~/.local/share/opencode/opencode.db* ~/opencode-db-backup/
npm install -g @opencode/cli@2.3.0
opencode service start
```

Use `sudo` for the global install if your npm prefix needs it. On OpenCode
2.2.4, AZPR 0.4.1 works and `/pr-check` shows the OpenCode WARNING row.

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.1
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.4.1'
```

Add only one of them. Follow the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.1/docs/QUICKSTART.md)
for a private PAT file, `/pr-setup`, a service restart and the first review.

## Upgrading AZPR

For an entry that `opencode plugin add` created, add 0.4.1 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.4.0:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.1 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running: OpenCode 2.2.4 and 2.3.0 switch the
running service to 0.4.1 within seconds, without a restart, and
`opencode plugin list` should then show a single `azpr` row with 0.4.1. Running
only the first command leaves the previous version running. For an entry with
options, change only its `package` value; the OpenCode service then downloads
0.4.1 with its own network settings. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.1/README.md#upgrading)
for the details. External settings, the PAT file and review records remain in
place, and no setting is new or required.

Reviews saved by 0.4.0 keep their previews, adjustments and sessions: the
sessions an earlier review kept are still deleted when that review is evicted.
They stay children of their conversation and are not in the session list.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

Manual copying needs the same files as 0.4.0.

## Compatibility and validation

The tested target is OpenCode CLI **2.3.0** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The prompts under `src/prompts` are unchanged, so reviews find and verify as
in 0.4.0. The
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.1/docs/VALIDATION.md#041-release-candidate-acceptance-2026-11-16)
lists the offline and real-host checks with fake services, on OpenCode 2.3.0
and again on 2.2.4, and the
[comparison of the two hosts](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.1/docs/VALIDATION.md#opencode-230-compared-with-224-2026-11-15-and-16).
No live review with a real model was run on this candidate, on either host.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts; the source archive also contains the
documentation, installers and settings example. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.4.1.tar.gz`, with checksums in `SHA256SUMS`.
