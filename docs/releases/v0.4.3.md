# Azure DevOps PR Review for OpenCode — 0.4.3

`/pr-setup` now sets AZPR up inside OpenCode's terminal UI: it asks for your
organization, a proxy if your network needs one, your token and a model,
checks the token with Azure DevOps and saves it in a file only you can read.
A first setup needs no restart. And after a review, the next thing you say in
the same conversation no longer costs one model request per AZPR notice. The
reviewer, verifier and comment-planning instructions are those of 0.4.2, and
no setting is new.

## What changed

- **Setup in dialogs.** A first setup used to mean creating the PAT file by
  hand in a terminal, typing a model ID, editing JSON for a proxy and
  restarting the OpenCode service. In the terminal UI, type `/pr-setup` and
  answer four questions: the organization (its name, or the URL of a pull
  request), a proxy (Enter skips it), the token, and a model from OpenCode's
  list.
- **The token stays hidden and is checked.** You paste it into a field that
  shows only how many characters it holds. AZPR asks Azure DevOps once
  whether it works for your organization and says what was refused: the
  token, the organization, or the way there. It is then saved alone in a
  file only you can read (mode 600), and is in no conversation, notice or
  log.
- **What could make setup fail is asked first.** The proxy comes before the
  token, because the token is checked over the network; after a proxy, the
  CA certificate file of a company that inspects HTTPS. If Azure DevOps still
  cannot be reached, the proxy or the CA file can be set right there and the
  same token tried again.
- **No restart after a first setup.** The review commands work at once, with
  the dialogs and with `/pr-setup --organization … --model …` alike. (A
  second project directory that the OpenCode service had already opened
  without settings still needs one, and says so.)
- **Settings as a list.** With settings in place, `/pr-setup` shows them with
  their values: organization, token, proxy, CA certificate file, the review,
  quick and deep models, output language, what follows a review, the report
  in the conversation, progress notices, the review panel and debug records.
  Choose one to change it. A change to settings that are in use takes effect
  after `opencode service restart`, and the list says so. Posting comments
  without a preview asks once more. Another organization asks for a token
  of its own: a saved token belongs to the organization it was checked for
  and is never sent to another one.
- **Options for one setting each**, for clients without the dialogs and for
  scripts: `--proxy`, `--ca-file`, `--review-model`, `--quick-model`,
  `--deep-model`, `--language`, `--after-review`, `--report`, `--progress`,
  `--panel` and `--debug`, without `--replace`.
- **A prompt after a review costs one request, not one per notice.** AZPR
  tells the conversation what a run does with notices (`STARTED`,
  `PROGRESS`, the receipts). They wait in the conversation's inbox and start
  no response of its model. Until now, when you then prompted that
  conversation, OpenCode 2.3.0 answered your prompt and after it gave each
  waiting notice a turn of the conversation's model: about eight more
  requests after a review with its comment preview, each carrying the whole
  conversation. The conversation's model now reads all waiting notices
  together with your prompt, in one request. In the terminal fixture, a
  prompt after 16 notices made 17 requests before and makes 1 now.

The dialogs need OpenCode's terminal UI. Other clients, such as the desktop
app, show `/pr-setup`'s instructions as before and take its options. The
dialogs only ask: the plugin's server part checks every answer, writes the
files and is the only part that contacts Azure DevOps. See
[setup](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.3/README.md#setup-in-the-terminal-ui).

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.3
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.4.3'
```

Add only one of them. Then open OpenCode's terminal UI and type `/pr-setup`;
the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.3/docs/QUICKSTART.md)
walks through it and shows the way without the terminal UI.

## Upgrading AZPR

For an entry that `opencode plugin add` created, add 0.4.3 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.4.2:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.3 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running. Running only the first command
leaves the previous version running. For an entry with options, change only
its `package` value; the OpenCode service then downloads 0.4.3 with its own
network settings. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.3/README.md#upgrading)
for the details. External settings, the PAT file and review records remain in
place, and no setting is new or required: an existing setup keeps working as
it is, and `/pr-setup` shows it as a list. Start the terminal UI again
afterwards: it loads a plugin's terminal part when it starts. Notices that
an earlier version left in a conversation's inbox stay as they are: each
still takes a request of its own when that conversation's model next runs.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

Manual copying needs one more file than 0.4.2, `src/tui-setup.mjs`: 35 in all.

## Compatibility and validation

The tested target is OpenCode CLI **2.3.0** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The prompts under `src/prompts` are those of 0.4.2, so reviews run, find and
verify as before. The
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.3/docs/VALIDATION.md#043-release-candidate-acceptance-2026-11-18)
lists the offline checks, the checks in the real terminal UI with fake
services (setup from a clean profile, from source and as the plugin manager
installs the package), the request that checks a token as a live Azure DevOps
organization answered it, and the measurements of how OpenCode 2.3.0 hands
waiting notices to a conversation's model. No live review with a real model
was run on this candidate, and the dialogs were not used against a live
Azure DevOps organization.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts; the source archive also contains the
documentation, installers and settings example. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.4.3.tar.gz`, with checksums in `SHA256SUMS`.
