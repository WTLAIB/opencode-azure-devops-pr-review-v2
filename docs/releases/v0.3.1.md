# Azure DevOps PR Review for OpenCode — 0.3.1

This release makes installation, first-run setup and upgrades easier to
follow on OpenCode 2.1.4, and lets `/pr-check` show which AZPR is running.
Reviews, comment previews, adjustments and publication work as in 0.3.0.

## What changed

- **Shorter setup.** `/pr-setup --organization YOUR_ORGANIZATION --model
  PROVIDER/MODEL` uses the PAT file the quickstart creates,
  `${XDG_CONFIG_HOME:-~/.config}/azpr/pat`, and `--organization` also accepts
  your PR's URL. With `--replace`, setup keeps the PAT file already set unless
  you name another one. The receipt names the organization and the PAT file.
- **See what runs.** `/pr-check` has an **AZPR** row that names the running
  package and version. When another AZPR entry is configured but not running,
  for example after `opencode plugin add` with a new version, which leaves the
  old one running, the row is a WARNING. User names, passwords and query
  strings in package specifications are masked.
- **Restart only for settings.** On OpenCode 2.1.4, adding or changing the
  plugin entry loads it into the running service within seconds. Saved
  settings still need a restart, and AZPR's messages now name
  `opencode service restart`.
- **Documentation.** The quickstart runs the terminal steps first. The README
  has an Upgrading section. The team guide explains proxies and certificates
  for package downloads, model providers and Azure DevOps separately, and the
  Azure DevOps guide names the actual settings locations.

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.3.1
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.3.1'
```

Add only one of them. Follow the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.3.1/docs/QUICKSTART.md)
for a private PAT file, `/pr-setup`, a service restart and the first review.

## Upgrading

For an entry that `opencode plugin add` created, add 0.3.1 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.3.0:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.3.1 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running: OpenCode 2.1.4 switches the running
service to 0.3.1 within seconds, without a restart, and `opencode plugin list`
should then show a single `azpr` row with 0.3.1. Running only the first command
leaves the previous version running. For an entry with options, change only
its `package` value; the OpenCode service then downloads 0.3.1 with its own
network settings. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.3.1/README.md#upgrading)
for the details. External settings, the PAT file and review records remain in
place, and this release adds no settings or required migration.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

## Compatibility and validation

The tested target remains OpenCode CLI **2.1.4** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The [validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.3.1/docs/VALIDATION.md)
describes the installation and upgrade behaviour measured on OpenCode 2.1.4
and the release checks with fake services. Setup and the AZPR row make no model
or Azure request, and reviews and publication are unchanged, so this release
needed no live model run.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.3.1.tar.gz`, with checksums in `SHA256SUMS`.
