# Azure DevOps PR Review for OpenCode — 0.2.2

This release brings the revised README and discovery metadata to npm. It
explains reviewing Azure DevOps PRs from a URL without maintaining a checkout,
model choices, separate verification, and comment previews. The runtime,
prompts, settings and installation behavior are unchanged from 0.2.1.

## What changed

- The README and quickstart share one first-review path:
  `/pr-review <PR URL> --preview`, with quick review as a lighter alternative.
- Compatibility explicitly excludes OpenCode 1.x. Detailed reference sections
  have visible navigation targets, and archive limits link to their actual guide.
- Azure Code Search is described as searching indexed branches; AZPR searches
  the selected commit snapshot. Model and performance claims stay within the
  documented evidence.
- The package has an updated description and the `opencode-v2` keyword.

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.2.2
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.2.2'
```

Add only one of them. Follow the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.2.2/docs/QUICKSTART.md)
for a private PAT file, `/pr-setup`, a service restart and the first review.

## Upgrading

Existing 0.2.1 installations do not need an update to receive a runtime fix;
this is a documentation and metadata release. To update a native installation,
edit its existing entry in the OpenCode configuration's `plugins` list:

- For npm, change the package specification to
  `opencode-azure-devops-pr-review@0.2.2`.
- For Git, change the tag suffix to `#v0.2.2`.

If the entry is an object, change only `package`; preserve `options.settingsFile`
and any other options. Keep one AZPR entry and restart the OpenCode service.
External settings, the PAT file and review records remain in place; a working
configuration needs no new `/pr-setup`. Exact version pins are not advanced by
`opencode plugin update`.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

Coming from 0.1.0, see the
[0.2.0 upgrade notes](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.2.0/docs/releases/v0.2.0.md#upgrading-from-010)
for automatic comments, which remain disabled unless configured or requested.

## Compatibility and release assets

The tested target remains OpenCode CLI **2.1.2** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated. See the
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.2.2/docs/VALIDATION.md).

The npm package comes from this tag and has no dependencies or install scripts.
Release assets are `opencode-azure-devops-pr-review-v2-0.2.2.tar.gz` and
`SHA256SUMS`; verify the source archive with `sha256sum -c SHA256SUMS`. The
existing demonstration remains attached to
[v0.2.0](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/releases/tag/v0.2.0),
with its original recording context documented in the
[demo guide](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.2.2/docs/DEMO.md).
