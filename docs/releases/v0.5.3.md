# Azure DevOps PR Review for OpenCode — 0.5.3

This release removes a known limitation of 0.5.2: with `shell: "ask"` or
`"inherit"`, a shell request of one of AZPR's sessions that a person declined
without a message left that session's turn open, and what OpenCode then did in
the session by itself could get a model request and tools. A turn now ends
where the execution that took its prompt ended, also at a step OpenCode
interrupted. The tested host stays OpenCode 2.4.2. The prompt files are those
of 0.5.2, no setting is new, and your settings and saved reviews are used as
they are.

## What changed

- **A declined shell request ends its turn at the declined step.** Declined
  without a message (OpenCode's full-screen terminal UI and its desktop app
  give none in AZPR's sessions), OpenCode interrupts that step and records
  the end of its execution as a shutdown, which leaves no marker of the turn's
  end. AZPR 0.5.2 counted a turn to the first such marker, so where something
  woke the session meanwhile (the notice of a background command that ended,
  say), AZPR let the model request and the tool calls of the execution that
  OpenCode started then through, refused the turn afterwards and tried the
  pass again in a new session. Now the declined step is the turn's end, also
  where another error came first in that step: nothing OpenCode starts in
  that session afterwards gets a model request, a retry or a tool, and the
  turn fails as interrupted (`failure=permanent`) and is not tried in a new
  session. A reviewer's first turn fails its pass, as it already did when
  nothing woke the session, and its stage line says `terminal=interrupted`
  (for a plain decline 0.5.2 said `terminal=missing-idle`); after a correction
  or follow-up turn, the latest usable answer stands where there is one, and
  the stage line names that turn's failure (`repair=failed:permanent`, say). A
  decline with a message (`opencode mini` asks for one) still lets the session
  go on with the message as the command's result.
- **A host fixture for declined requests.** `tests/host-v2-decline.mjs` runs
  four reviews on the real host with a fake model: a request declined without
  a message; one declined after a background command ended; the same where the
  declined step also ended with a finish reason OpenCode does not know, so that
  its message carries that error; and one declined with a message. It also
  holds the forms of OpenCode that AZPR tells such an end by, and runs in CI.
- **CONTRIBUTING names the fixture runs each kind of change needs.** It spoke
  of "the last two" runs where six runs of the terminal UI follow.

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.5.3
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.5.3'
```

Add only one of them. Then open OpenCode's terminal UI and type `/pr-setup`;
the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.3/docs/QUICKSTART.md)
walks through it and shows the way without the terminal UI.

## Upgrading AZPR

For an entry that `opencode plugin add` created, add 0.5.3 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.5.2:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.5.3 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running. Running only the first command
leaves the previous version running. For an entry with options, change only
its `package` value. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.3/README.md#upgrading)
for the details. Settings, the PAT file and review records remain in place,
and no setting is new or required. Coming from 0.4.x, the settings need the
update that the
[0.5.0 release notes](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.3/docs/releases/v0.5.0.md)
describe. OpenCode stays at 2.4.2; coming from an earlier OpenCode, the
[0.5.2 release notes](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.3/docs/releases/v0.5.2.md#upgrading-opencode)
give the upgrade.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

Manual copying needs the same 33 files as 0.5.2.

## Known limitations

Changed by this release: a shell request declined without a message still
fails that session's turn, which is not tried in a new session; what OpenCode
does in the session after the declined step is no longer authorized. Approve
the command, or keep `shell: "deny"` where AZPR's sessions should run none;
see
[debugging](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.3/docs/DEBUGGING.md#diagnosis-order).

Not changed by this release: the other limitations that the
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.3/docs/VALIDATION.md#known-limitations)
keeps current.

## Compatibility and validation

The tested target is OpenCode CLI **2.4.2** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. `/pr-check` notes other OpenCode versions in its OpenCode row.
OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The prompt files under `src/prompts` are unchanged. The
[release candidate's acceptance](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.5.3/docs/VALIDATION.md#053-release-candidate-acceptance-2026-11-28)
says what 0.5.3 ran on and what was only read from OpenCode's source.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts; the source archive also contains the
documentation, installers and settings example. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.5.3.tar.gz`, with checksums in `SHA256SUMS`.
