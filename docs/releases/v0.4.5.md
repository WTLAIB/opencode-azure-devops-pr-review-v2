# Azure DevOps PR Review for OpenCode — 0.4.5

While a run is under way, the panel beside the conversation now offers to
stop it, so the command and the run's ID need not be found in the
conversation and typed. The reviewer, verifier and comment-planning
instructions are those of 0.4.4, and no setting is new.

## What changed

- **A run is stopped from the panel.** A `STARTED` notice says how its run is
  stopped (`/pr-stop <run-id>`), but in the conversation, with an ID to copy.
  While a run is under way (a review, a preview that is being planned, a
  publication, a check) the row at the panel's foot now offers one step:

  ```text
  [s] Stop this run…
  ```

  Click it, or press `s` while the panel has the keyboard. After the run's
  receipt the row shows what that receipt offers, as before: the steps of a
  preview, or nothing.
- **Stopping asks first.** The question's first row is "No, let it run", and
  it names the run, so a key pressed twice stops nothing. "Yes, stop it"
  sends `/pr-stop` with that run's ID to the session on screen, and AZPR
  takes it like a typed command: the run ends with its `CANCELLED` receipt.
  Requests that were already sent may still be billed, as with the typed
  command.
- **Only the run you were asked about is stopped.** An answer is acted on
  only while the panel still shows that run as under way. If it has ended, or
  the next run has started (the preview that follows a review by itself, for
  instance), while the question was open, nothing is sent and the panel says
  so. A step that reaches AZPR after its run has ended stops nothing, and no
  other run.
- **A run that has ended is not waited for.** Where the panel has no report or
  preview to show, it said "No report or preview yet." also of a run that had
  ended, such as one that was stopped. Once the run has its receipt it now
  says "This run ended with no report or preview to show."
- **A click on a step is not lost.** Since 0.4.4 the steps at the panel's foot
  were drawn anew whenever the panel worked its content out again, and a
  press or a release that came before the next frame went nowhere: now and
  then a click did nothing, most likely right after a notice arrived. Each
  step now keeps its element.

The step needs OpenCode's terminal UI. Other clients, such as the desktop
app, show AZPR's notices as before, and `/pr-stop` is typed as before. That a
run can be stopped travels with its `STARTED` notice as data no model reads;
the text of every notice is unchanged. See the
[terminal panel](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.5/README.md#terminal-panel).

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.5
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.4.5'
```

Add only one of them. Then open OpenCode's terminal UI and type `/pr-setup`;
the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.5/docs/QUICKSTART.md)
walks through it, with a recording of the dialogs, and shows the way without
the terminal UI.

## Upgrading AZPR

For an entry that `opencode plugin add` created, add 0.4.5 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.4.4:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.5 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running. Running only the first command
leaves the previous version running. For an entry with options, change only
its `package` value; the OpenCode service then downloads 0.4.5 with its own
network settings. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.5/README.md#upgrading)
for the details. External settings, the PAT file and review records remain in
place, and no setting is new or required. Start the terminal UI again
afterwards: it loads a plugin's terminal part when it starts. A run that an
earlier version started offers nothing to pick; stop it by typing the command
its `STARTED` notice shows.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

Manual copying needs the same 36 files as 0.4.4.

## Compatibility and validation

The tested target is OpenCode CLI **2.3.0** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The prompts under `src/prompts` are those of 0.4.4, so reviews run, find and
verify as before. The
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.5/docs/VALIDATION.md#045-release-candidate-acceptance-2026-11-20)
lists the offline checks and the checks in the real terminal UI with fake
services: a review that was stopped from the panel's foot, with a click and
with the key, after the question was declined once. It also records what
0.4.4 showed in real use: a review with a real model whose preview was
adjusted and posted. The step that stops a run was not used on a run of a
real model.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts; the source archive also contains the
documentation, installers and settings example. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.4.5.tar.gz`, with checksums in `SHA256SUMS`.
