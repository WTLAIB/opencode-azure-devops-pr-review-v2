# Azure DevOps PR Review for OpenCode — 0.4.4

After a comment preview, the panel beside the conversation now lists what you
can do next at its foot, and picking one does it: post the comments, leave
findings out or change a level, reset that. A conversation used for a review
is named after its PR instead of staying "New session", and several texts of
setup say more exactly what they mean. The reviewer, verifier and
comment-planning instructions are those of 0.4.3, and no setting is new.

## What changed

- **The next step is in the panel.** A receipt ends with the commands for the
  next step, but the panel shows the report or preview, so those commands had
  to be found in the conversation and typed. After a preview the panel lists
  them in one row at its foot, where reading ends, and the row stays in place
  while the text scrolls:

  ```text
  [p] Post 4 comments…   [a] Adjust findings…   [u] Reset adjustments
  ```

  Click one, or press its key while the panel has the keyboard; the keys are
  drawn dim while they would only type a letter into the prompt. A label that
  ends in `…` asks before anything is sent. **Reset adjustments** is there
  once something was adjusted.
- **Posting asks first.** The question's first row is "No, post nothing", so
  a key pressed twice posts nothing.
- **Findings are adjusted from a list.** The findings are listed with how
  each is published now. Pick one to leave it out or to choose its level, and
  apply every change at once from the foot of the list (**apply**, `ctrl+s`),
  which stays in view however long the list is; the preview is then planned
  again and shown from its beginning. No finding ID is typed.
- **They send the command you would type.** Each sends `/pr-comment` with
  the ID of the review the panel shows, to the session on screen, and AZPR
  takes it like a typed command: the same checks, the same `STARTED` notice
  and receipt. The panel sends nothing by itself and never a prompt, and the
  steps are there only for the notice that happened last. After a review that
  no preview follows by itself (`afterReview: none`), the row offers
  **Preview comments** (`c`) instead of posting.
- **Nothing is posted that you have not read.** A click on one of the steps
  leaves the keyboard with the prompt. An answer is acted on only while the
  panel still shows what you answered for: if the preview is planned again,
  another session comes on screen or the panel is closed while a question is
  open, nothing is sent and the panel says so. Each command the panel sends
  also says which preview and adjustments it was picked for (`--seen`), and
  AZPR refuses it when they have changed somewhere the panel was not told
  of, such as the review's own session or another client. A preview that another
  command adjusted, planned again or posted while its own run was ending is
  no longer shown as a preview: that run says "Preview replaced before its
  receipt" in one line, and the other command's receipt is the one to read.
- **A session that has answered is `finished`.** While a review ran, a
  reviewer session that had answered was shown as `idle`, OpenCode's word for
  a session at rest, which read like a fault. It is `finished` now, until the
  run's receipt names its result.
- **A conversation is named after its PR.** OpenCode names a conversation when
  its own model first runs there, which an AZPR command never makes it do. A
  check or a review now names a conversation nobody named, for example
  `AZPR: PR #123 (repository)`. A name that is there stays, also one that you
  or OpenCode's model give it in that very moment: AZPR follows the renames
  OpenCode reports and puts such a name back.
- **Setup says more exactly what it means.** The settings list says what each
  model is for, and the deep model's dialog what makes one: a model stronger
  than the review model, or the same model with a higher variant, which
  reasons longer. "Settings file" names the section of the README that
  describes every setting. And where AZPR has no usable settings, the command
  list says "AZPR is not ready here; run /pr-setup to see what it needs",
  which also holds when the settings were saved from another project
  directory and only a restart is missing.

The steps in the panel need OpenCode's terminal UI. Other clients, such as the
desktop app, show AZPR's notices as before, and every command is typed as
before, without `--seen`. What is offered travels with the notice as data no
model reads; the text of the notices is unchanged, except for the one line a
replaced preview's run now says instead of its receipt. See the
[terminal panel](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.4/README.md#terminal-panel).

## Installation

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.4
```

Alternatively, install the same release from Git:

```sh
opencode plugin add 'github:WTLAIB/opencode-azure-devops-pr-review-v2#v0.4.4'
```

Add only one of them. Then open OpenCode's terminal UI and type `/pr-setup`;
the
[quickstart](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.4/docs/QUICKSTART.md)
walks through it, with a recording of the dialogs, and shows the way without
the terminal UI.

## Upgrading AZPR

For an entry that `opencode plugin add` created, add 0.4.4 and remove the
previous version only when the download succeeded. Replace `PREVIOUS_VERSION`
with the version in your `plugins` entry, such as 0.4.3:

```sh
opencode plugin add opencode-azure-devops-pr-review@0.4.4 &&
  opencode plugin remove opencode-azure-devops-pr-review@PREVIOUS_VERSION
```

Run them when no AZPR command is running. Running only the first command
leaves the previous version running. For an entry with options, change only
its `package` value; the OpenCode service then downloads 0.4.4 with its own
network settings. See
[upgrading](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.4/README.md#upgrading)
for the details. External settings, the PAT file and review records remain in
place, and no setting is new or required. Start the terminal UI again
afterwards: it loads a plugin's terminal part when it starts. A preview that
an earlier version left in a conversation offers nothing to pick; run
`/pr-comment --show` to see it again with its steps.

For a source installation, extract the new archive and run its installer with
`--replace` to retain settings:

```sh
sh install.sh --config-dir /absolute/path/to/v2-opencode-config --replace
```

Manual copying needs one more file than 0.4.3, `src/tui-actions.mjs`: 36 in all.

## Compatibility and validation

The tested target is OpenCode CLI **2.3.0** (V2 plugin API), Node.js
**22.23.3**, Ubuntu **22.04.5** under WSL2, and Azure DevOps Services REST API
**7.1**. OpenCode 1.x and Azure DevOps Server are not supported; other operating
systems remain unvalidated.

The prompts under `src/prompts` are those of 0.4.3, so reviews run, find and
verify as before. The
[validation record](https://github.com/WTLAIB/opencode-azure-devops-pr-review-v2/blob/v0.4.4/docs/VALIDATION.md#044-release-candidate-acceptance-2026-11-19)
lists the offline checks and the checks in the real terminal UI with fake
services: findings left out and the comments posted from the panel's foot,
a conversation named by a check, and the texts of setup. It also records what
0.4.3 showed in real use the day before: a first setup in the dialogs against
a live Azure DevOps organization, and a review with a real model whose ten
notices reached the conversation's model in one request. The steps at the
panel's foot were not used against a live Azure DevOps organization.

The npm package, Git package and source archive contain the same runtime, with
no npm dependencies or install scripts; the source archive also contains the
documentation, installers and settings example. The release source artifact is
`opencode-azure-devops-pr-review-v2-0.4.4.tar.gz`, with checksums in `SHA256SUMS`.
